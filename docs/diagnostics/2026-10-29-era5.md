# ERA5 and repository diagnostic — 2026-10-29

The audit started from `main` at `abebfa9` and traced source imports, public
package exports, notebook callers, dependency resolution, ingestion tests,
shared compatibility aliases, and dashboard/browser regressions.

## Findings and changes

| Finding | Resolution |
| --- | --- |
| Regional `scrapers/era5.py` and global `scrapers/era5_global/` looked like competing implementations. | Both are active. Grouped them under `scrapers/era5/regional.py` and `scrapers/era5/global_temperature/`. The notebook uses regional ingestion; the configured `weather/era5.py` CLI uses global temperature streaming. |
| Empty `scrapers/ecmwf.py` did not provide a provider package to extend. | Replaced with `ecmwf/__init__.py` and `.gitkeep`; it remains an unimplemented forecast-ingestion scaffold. |
| `weather` required Zarr 3 while `era5` required Zarr 2. Installing both extras failed dependency resolution; the global decoder failed under the weather-only installation. | Both extras use Zarr 2.18–2.x. Regional xarray is constrained to `>=2024.10,<2026`; recent xarray versions require the Zarr 3 Python API. A real local Zarr round-trip verifies regional compatibility alongside global Zarr decoder fixtures. |
| A scheduling test assumed one file per day for a two-variable request. | It now verifies fourteen variable files over seven distinct UTC days, both variables per day, and the original concurrency/lookahead bounds. |
| A notebook test and guide assumed two code cells although the notebook has settings, imports, and retrieval cells. | Corrected the three-cell expectation and instructions; notebook execution/resume is exercised with fixture data. |
| `scripts/datasets.save()` called pandas' `to_csv` on Polars tables and silently reported failure. | Dispatches Polars tables to `write_csv`, retains the existing pandas-style method fallback and 1/-1 return codes, and removes unused plotting/pandas imports. Corrected its standalone example's missing `era5` lake path segment. Added round-trip and failure tests. |
| Moving the global package could break old imports, class references, or module state. | Legacy `era5_global` paths are lazy aliases to canonical modules. Alias chains are flattened, preserving module identity/specs, reloads, classes, and globals through both market and legacy infra import paths. |

The existing global CLI/settings file and regional public imports remain
supported. A grouped `python -m comm_research.markets.weather.scrapers.era5`
CLI is also available. Defaults, date semantics, lake schemas, units, raw/state
paths, resume checks, and atomic-write behavior are preserved. No stored lake
files were migrated or refreshed.

See the [package map](../markets/weather/era5/README.md) for the new tree,
regional/global output differences, installation commands, and compatibility
imports. Existing environments should reinstall the extras and restart their
notebook kernel after pulling:

```bash
python -m pip install -e '.[weather,era5,notebooks]'
```

## Validation

- Repository Python regressions include CAISO ingestion, dashboards, rendering,
  zoom/pan, storage/resume behavior, ERA5 NetCDF decoding, HTTP/Zarr fixtures,
  notebook execution, public exports, and legacy imports. Added CSV tests cover
  Polars round-trips, pandas-style callers, and unchanged failure status codes.
- New package checks cover both legacy import orders, chained aliases, canonical
  module specs, old class references, cheap parent imports, scaffold visibility,
  both CLI entrypoints, and a real regional Zarr read/write cycle.
- JavaScript tests, dependency consistency, focused lint, documentation links,
  notebook syntax/state preservation, and whitespace checks were checked.
- Built and installed a wheel outside the checkout, checked both CLI forms,
  canonical/legacy imports and the packaged scaffold, and verified no duplicate
  old ERA5 implementations were shipped.
- Validation used local and HTTP-mocked fixtures. It did not submit CDS jobs,
  inspect credential values, or download a global reanalysis day/backfill.

The existing 224-test suite passed without skips after the notebook correction;
all 20 JavaScript tests passed. After adding the CSV tests, the combined
227-test run passed 226 tests and hit one intermittent existing 50ms browser
paint threshold. Its update maximum was 21.5ms and paint p95 was 33.5ms, but
one two-frame RAF measurement reached 233.8ms. The same unchanged timing test
passed in isolation (update maximum 25.3ms, paint maximum 34.0ms), retaining its
canvas and making no API requests. No dashboard rendering code or timing
assertions were changed. This hardware/load-sensitive timing gate remains
intermittent; the report does not represent that combined run as fully green.

the refactored scraper implementation and CSV utility:

| Area | Findings |
| --- | ---: |

These are static/style issues such as imports, literal construction, existing
validation exception conventions, and fixture execution. They are recorded
rather than mixed into a broader research-code rewrite. Focused lint for all
new scraper packages, entrypoint, compatibility loader, package tests, layout
tests, and CSV helper/tests passes.

`PCB.debiasPP`, `PCB.persistencePP`, and `PCB.predict` are still empty research
methods. No forecasting or correction model was implemented or validated in
this ingestion/package diagnostic. The regional and global temperature tables
also retain their different schemas; readers must select the intended dataset
rather than assume every file under the common temperature prefix has one schema.
